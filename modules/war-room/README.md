# War Room

War Room v0.8.0 is the Suite's unified combat workspace and the preparation release for its next major update.

Best Formation search supports explicit runs of 25, 50, 75, 100, 150, or 200 native simulations.

War Room follows the Suite 1.0 module contract through `manifest.json`, the standard `index.js` entry point, the `Module` base class, the `enable/disable/destroy` lifecycle, explicit capability permissions, and the versioned custom-renderer bridge. Its module version remains independent from the framework and Hub API versions.

Data flow:

`ClientLib -> GameDataHub -> WarRoomHub -> analyzers -> WarRoomWindow`

Sections:

- Search and Target Information
- Attack Planner
- Battle Simulator
- Report Summary
- Army Analyzer
- Combat Statistics

Search is the first/default tab and reuses the shared Scanner Hub discovery service. It can search from the current attacker base by target type, minimum/maximum level, and maximum command-point cost. Level defaults span the current offense level through five levels above it, while maximum CP defaults to 41; CP replaces the former visible distance filter. Base, Camp, and Outpost filters cover Forgotten targets, while PVP discovers other players. Alliance mode is mutually exclusive and asynchronously populates its deduplicated selector from the server's current alliance ranking rather than stale sector dictionaries. Player and alliance identity is resolved from the live region object at each world coordinate. A normal result-row click selects the target and loads its intelligence without leaving Search; only the row's **Open Attack** cell enters native combat setup. Completed searches can be downloaded as a spreadsheet-ready CSV, copied as an in-game BBCode coordinate list, or opened as a draft in Communications for review and manual sending. Shared exports intentionally omit CP because that cost is specific to the searching base. Army Analyzer and Combat Statistics also provide CSV downloads for their current base/filter view. Search only discovers targets; it does not own War Room selection. The target currently open in a native attack screen remains authoritative for combat tabs. The same rule applies when an attack screen is opened from the world map or another tool.

Attack capacity distinguishes fully repairable hits from total attack opportunities. Repair storage divided by the conservative largest offense-group repair requirement gives the fully recoverable count; War Room then includes one final hit whose damage may remain partially unrepaired, with the result still capped by command points.

Select an attacker and target in the game before opening or refreshing War Room. The simulator action opens the native combat-setup view. Native battle results, attack history, and favorite targets persist locally between sessions. Alliance-shared intelligence remains a planned extension.

Attack Planner analyzes the current offensive formation and loaded target defense, then renders a visual 9×4 recommendation for Construction Yard, Defense Facility, Command Center, total defense damage, or maximum Research Points goals. Its initial preview uses unit roles and lane threats. Preview editing remains reversible inside War Room, with movement, mirror, row-swap, undo, reset, and manual-simulation controls shown in the planner. Its scrollable left result card uses the same defender, repair, loot, outcome, and duration presentation as cached Battle Simulator cards; both best-formation searches and **Simulate Preview** publish their complete result there. While native attack setup is open, a movable, native-themed Formation Controls palette appears beside the lower-right edge of the play area. Its 31-pixel icon buttons use a narrow 3×6 arrangement inspired by the established formation pad: simulation/open controls, directional movement, mirrors, visibility groups, reset/save, and three row swaps are grouped by function. It can toggle all or selected troop groups, enter a persistent single-troop hide/show mode, open War Room, restore the attack-screen starting layout, or save the current formation. Its position is retained. Clicking Simulate Best Formation submits non-destructive candidates to the game's native `SimulateBattle` command and ranks the returned combat results by the selected objective. The candidate search does not move live units and observes the game's simulation cooldown.

The single-troop hide/show icon delegates to the native attack setup's persistent `btn_disable` mode. While active, each troop clicked in the game is toggled by the game itself and the mode remains active until the Suite icon is clicked again. Runtime selection matching is retained only as a compatibility fallback when a client build does not expose the native control.

War Room compacts the native attack setup while its module is enabled: the redundant large horizontal extended-control section is excluded and each formation row receives faction-themed mirror/left/right controls beside it. The game's original per-column controls remain untouched because they already provide the correct active/idle behavior and are rebuilt internally whenever native controls are used. The adapter discovers named/structural Qooxdoo containers without modifying obfuscated game methods and restores the original widgets when War Room is disabled.

Manual troop movement in the native attack screen is polled from the live formation. A detected change—or an explicit **Refresh**—rebuilds the Attack Planner preview, army information, cached-result presentation, and native live-simulation key from the current game coordinates and enabled state. Optimizer recommendations are generated only when the user requests them and no longer hide a manually arranged live formation during refresh.

Each distinct manually arranged formation automatically queues a native simulation and becomes a separately labeled **Manual layout** entry in Battle Simulator as soon as its result returns. The entry retains the exact unit coordinates and enabled state, can be loaded into the reversible preview, applied through the explicit formation confirmation, or replayed in the native battle viewer. Rapid moves are coalesced around the game's simulation cooldown, while every completed distinct result remains cached for comparison.

The user-initiated **one-click formation arranger** can apply the displayed preview or any cached simulated formation to the active attack setup through the game's formation movement API. It requires explicit confirmation, never launches an attack, and remains independently disableable with `EXPERIMENTAL_ONE_CLICK_FORMATION_ENABLED` without removing read-only planning or simulation.

Formation presets are stored persistently by the exact attacking-base and target-ID pair. A preset captures unit positions and enabled state, can be overwritten by saving the same name for that same target, and is shown or loadable only when both its attacking base and target are active. Loading also validates the target before changing the live combat-setup formation and queuing a fresh native simulation. Targets with saved formations receive a faction-colored map base plate—cyan/blue for GDI and orange/red for NOD—through a reversible Suite renderer hook, making prepared targets visible from region view.

The Battle Simulator automatically shows the current and cached native results as sortable text data plus side-by-side result cards. Each card includes defender condition, offensive repair time by unit group, Tiberium/Crystal repair costs (plus any additional resources returned by the game), loot, outcome, and duration. Attack Planner results show the same repair requirement before a formation is applied. Its **Sim** button switches the main game play area to that exact cached battle animation; **Use** arranges the active formation after confirmation. Compact selected-unit arrows and Hide/Show controls edit the reversible preview before **Use Preview** commits it. Automatic simulations caused by troop movement update results silently and never interrupt combat setup.

Report Summary filters the game's native Offense, Defense, The Forgotten, and Others report categories. It requests report headers and full records through the game's `Reports` manager (`GetReportCount`, `RequestReportHeaderDataAll`, and `RequestReportData`), displays each delivered attack, resolves native loot and repair data, and adds category totals for victories, CP, resources per CP, and repair time. Native report/replay handoff tries the exposed viewer, direct report combat replay (including runtime loader discovery), then the native Reports window. Refresh performs a new native request rather than reading a guessed in-memory collection.

Army Analyzer lists every owned base that has a Command Center and can display that base's offensive army. It provides unit role, level, health, enabled state, grid position, range, speed, native preferred armor/target class, an explicitly estimated 1v1 level ceiling, and Crystal repair cost, plus formation composition, damaged/hidden counts, average level/health, and a readiness index. Its page-specific **Repair All Troops** action repairs the selected base's offense directly and does not depend on opening or enabling Repair Manager. The ceiling is a comparison aid—not a native battle result—so final decisions should use native simulation.

Combat Statistics loads native reports through a serialized query pipeline and preserves the live game's four authoritative folders: **Offense** is attacking Forgotten, **Defense** is defending against players, **The Forgotten** is defending against Forgotten, and **Others** is attacking other players. It publishes the four categories atomically so partial refreshes cannot change displayed counts, and its base selector comes only from the authoritative owned-base collection. Its compact transposed table includes reports, wins/losses, success rate, loot, and clock-formatted average repair time. Historical CP and loot-per-CP are intentionally omitted because Raid Reports do not reliably publish the original command-point cost. The former duplicate troop-movement strip was removed from Battle Simulator; formation editing remains in Attack Planner and the live Formation palette.

Report Summary presents the game's Raid Report records newest first. Every row shows the attacking base, target name and coordinates, result, command points, separate Tiberium/Crystal/Credits/Research/other loot and repair time. Its **Open Reports** action opens the native Reports page and selects the corresponding record; War Room prioritizes the native full-data request handler in an attempt to open Raid Report details, but the current client does not publish historical battle animation data in the summary record itself.

# Repository Structure

> Status: Implemented for v1.0.0

The source repository is divided by responsibility.

- `core/` contains framework-owned services and must not depend on feature modules.
- `modules/` contains optional or user-facing features.
- `manifest/chrome/` contains browser entry points.
- `scripts/build/` generates the module catalog and release build.
- `tests/` contains automated and manual validation.
- `docs/` contains specifications and references.
- `dist/chrome/` is generated output and should not be edited directly.

## Core boundaries

- `core/bootstrap/`: startup ordering and lifecycle.
- `core/clientlib/`: ClientLib and Qooxdoo discovery.
- `core/game/`: game-facing services and public facade.
- `core/modules/`: module contracts, loading, dependencies, permissions, and settings.
- `core/ui/`: reusable native Qooxdoo components and top-bar integration.
- `core/windows/`: windows, dialogs, notifications, and window behaviors.
- `core/events/`, `core/storage/`, `core/settings/`, `core/theme/`, and `core/diagnostics/`: shared infrastructure.

## Generated files

`core/modules/moduleCatalog.generated.js` is generated by the build tooling. Do not edit it manually.

## Module boundaries

Modules should use `ModuleContext` capabilities rather than importing private core implementations. Core must never import feature-module code except through the generated catalog.

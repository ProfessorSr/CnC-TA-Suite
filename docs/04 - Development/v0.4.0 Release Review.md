# v0.4.0 Release Review

Date: 2026-07-19

## Scope

This review inspected the current repository structure, release metadata, startup composition, module runtime, native UI direction, generated module catalog, documentation state, tests, and Chrome build.

## Validation performed

- `VERSION` is `0.4.0`.
- `PART` is `v0.4.0-release`.
- Chrome manifest version is `0.4.0`.
- Chrome build completed successfully.
- Module catalog generation found four modules.
- Automated tests completed with 29 passes and 0 failures.

## Architecture assessment

The project has reached a coherent pre-1.0 foundation:

- startup waits for Qooxdoo;
- shared services are composed centrally;
- Module Manager is core-accessible through the game top bar;
- windows, notifications, dialogs, and controls are Qooxdoo-native;
- modules are discovered and lifecycle-managed;
- game integration is separated from feature modules;
- diagnostics and test coverage are present.

This supports treating v0.4.0 as the point after which normal work should be refinement rather than structural reconstruction.

## Follow-up findings

### Permission registry alignment

`ModuleContext` includes a `qx` capability, but `ModulePermission` does not list `qx`. A manifest requesting it will fail validation. Add `QX: 'qx'` to the explicit permission registry or remove the manifest-facing capability.

### Legacy DOM helper

`core/utils/dom.js` remains in the source tree but no current core or module import was found during review. Remove it after confirming no external module depends on it, or mark it as compatibility-only.

### Documentation debt

Many historical specification files still contain placeholder text. The release package updates the most important implementation-facing documents, but remaining placeholders should be replaced incrementally before v1.0.0.

### Live-game acceptance

Automated validation cannot replace testing against a live Tiberium Alliances world. Complete the manual integration checklists before public release.

## Release recommendation

v0.4.0 is suitable as the stable architectural baseline. Proceed with targeted fixes and polish toward v1.0.0 while avoiding unnecessary rewrites.
